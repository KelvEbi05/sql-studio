What you will learn

    Query clinic: write, read and fix SQL errors

    Build a query in a safe order

    1. Start with SELECT and name only the columns you need.
    2. Add FROM, then run the small query before adding more.
    3. Add one clause at a time: WHERE, then GROUP BY, then ORDER BY.
    4. Use a semicolon at the end and format each clause on its own line.
    SELECT student_name, score
FROM dbo.students
WHERE score >= 70
ORDER BY score DESC;

    Why SQL is designed in clauses

    SQL describes the result you want, rather than every step used to find it. Each clause answers one question: FROM chooses the data, WHERE removes unwanted rows, GROUP BY creates groups, HAVING filters groups, SELECT chooses what to display, and ORDER BY arranges the final answer.

    Write in the familiar order: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY. Think through it as: data → row filter → groups → group filter → display → sort.

    Read errors like clues

    Invalid column name
    Check the spelling and the table alias. Use the dataset’s column list; a column might belong to a different table.
    Incorrect syntax near...
    Look just before the named word for a missing comma, bracket, quote, or keyword.
    Ambiguous column name
    Two joined tables have that column. Prefix it, for example s.student_name.
    Conversion failed
    SQL tried to treat text as a number or date. Check quotes and use the correct data type.

    A simple debugging loop

    1. Read the exact message and line number. Do not guess.
    2. Reduce the query to the smallest SELECT ... FROM ... that runs.
    3. Add back one clause at a time until the error returns.
    4. Check the result, not only whether it ran: row count, duplicates, missing rows and sort order all matter.

    What to check when you see an error

    • Read the full message and line number first.
    • Check the line above the named word for commas, brackets, quotes and missing keywords.
    • Confirm table names, column names and aliases against the schema.
    • Temporarily remove the newest clause and add it back in small pieces.
    • After it runs, verify the returned rows are actually the answer you intended.

    Before you press Run

    • Every selected column either appears in GROUP BY or is inside an aggregate such as COUNT.
    • Text and dates use single quotes: 'Ada', never double quotes.
    • Use IS NULL, never = NULL.
    • When joining, state the matching keys in ON and use table aliases consistently.

    This site explains the learning query when it fails. In SSMS, the error wording may be different, but the same debugging process applies.
